Pourquoi ce split ?

Decoder en Python : Le code de Mowokuma marche deja. Utilise Unicorn Engine pour emuler les fonctions de dechiffrement du binaire LoL. Aucune raison de reecrire.

Extractor en Ruby : C'est la ou 80% du temps de dev passe (logique de detection, reconnaissance de patterns). L'auteur est dev senior Ruby -- iteration la plus rapide dans ce langage.

Fichier intermediaire de 135MB : Feature, pas bug. Permet de debugger decoder et extractor independamment. Re-lancer l'extractor sans re-decoder.

2 Data Flow

Step 1 -- Decoder (Python)

Input : fichier .rofl

Process :

  1. Parse header + metadata (JSON non chiffre -- scoreboard post-game)
  2. Dechiffre les chunks via Blowfish (cle = match ID)
  3. Decompresse (zstd/zlib)
  4. Decode les paquets individuels en emulant les fonctions du binaire LoL via Unicorn Engine
  5. Necessite un patch file par version de LoL

Output : JSON brut avec 20 types de paquets :

PaquetDonnees
CastSpellAnsChaque cast d'ability (spell, position, cible, cooldown, mana cost)
BasicAttackPosChaque auto-attack (source, cible, positions)
WaypointGroupMouvements des joueurs (coordonnees x,z ~1/seconde)
UnitApplyDamageChaque instance de degat
HeroDieMorts de champions
BuyItemAchats d'items
EnterFog / LeaveFogEntrees/sorties du fog of war
ReplicationDataSync d'etat du jeu (HP, mana, stats)
DoSetCooldownMises a jour de cooldowns
CreateHeroSpawn/init des champions
CreateNeutralCreation des monstres neutres
CreateTurretInitialisation des tourelles
NPCDieMapViewMorts de NPCs
Contrainte majeure : Le patch file doit etre regenere a chaque patch LoL (~toutes les 2 semaines). Il faut dumper les sections du binaire League of Legends.exe (Windows) et trouver les adresses des fonctions de dechiffrement.

Step 2 -- Extractor (Ruby)

Input : JSON brut + summoner name + role

Pipeline :

1. LOAD -- Lire le JSON brut + identifier ton summoner
2. FILTER -- Garder seulement ton champion + mid adverse + junglers
3. DETECT -- Reconnaitre les "moments" gameplay
4. ENRICH -- Ajouter contexte (vision, wave, gold, objectifs)
5. AGGREGATE -- Calculer les patterns globaux
6. EXPORT -- Sortir le JSON compact

Types d'evenements detectes :

TypeDetecte depuisChamps cles
TRADEUnitApplyDamage + CastSpellAns dans ~3shp_before/after, abilities, result
DEATHHeroDie sur ton championkilled_by, position, gold_unspent, wards
CS_STATESnapshot periodiqueyour_cs, enemy_cs, cs_diff
ROAMWaypointGroup hors zone middestination, wave_state, result
TEAMFIGHT3+ HeroDie dans ~2000u en ~15stargets, entry_timing, ult
RECALLEnterFog + immobile ~8sobjective_soon, gold_unspent

Step 3 -- Reviewer (Claude)

V1 : Manuel via Claude Code. Tu lances bin/review game.rofl, tu obtiens review.json, tu le donnes a Claude Code avec le prompt template.

V2 : Automatise via API Claude. bin/review sort directement la review texte.

7 Risques

!
Mowokuma arrete la maintenance -- Plus de patch files pour les nouvelles versions
Mitigation : Apprendre a generer les patch files soi-meme des le debut
!
Vanguard bloque le dump du binaire -- Impossible de generer les patch files
Mitigation : La communaute trouvera des contournements ; fallback sur Riot API
~
Format .rofl change fondamentalement -- Le decoder casse
Mitigation : Peu probable, le format est stable depuis des annees
~
JSON de 135MB trop bruyant -- Mauvaises detections
Mitigation : L'extractor Ruby filtre agressivement ; iterer sur les seuils
?
Hallucinations de Claude -- Mauvais conseils gameplay
Mitigation : JSON structure reduit les hallucinations ; prompt engineering
